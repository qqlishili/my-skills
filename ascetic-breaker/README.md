## 🤔 为什么需要"破执"？

大多数 AI 写代码的套路是：

> *"拿到需求，激活预训练知识，从头推导，从头写。"*

然后产出的代码——版本不兼容、API 签名靠猜、项目里明明有工具函数却重写了一遍。像一个苦行僧，明明有桥，偏要涉水过河，还觉得自己"在认真修行"。

**破执术的思路完全不同**——它不替智能体检索，而是在它"埋头苦推"时断喝一声：

```
马祖道一（700年）    →  即心即佛 → 非心非佛 → 无佛可求
CSDN 工程分析（2024） →  环境好奇心缺失的 5 个根因
拉康精神分析         →  苦修 = 用肉体的苦换符号界的积分 = 自我膨胀
```

这不是玄学，这是**元认知工程**：

| | 埋头硬推 | RAG 外挂 | **破执术** |
|---|:---:|:---:|:---:|
| **缺口检测** | ❌ 不检查 | ⚠️ 被动检索 | **✅ 主动扫描5类缺口并评分** |
| **项目内复用** | ❌ 重写 | ❌ | **✅ P0优先 Glob/Grep** |
| **多方案选择** | ❌ 拍脑袋 | ⚠️ 返回top-k | **✅ 六维评分（版本一票否决）** |
| **交叉验证** | ❌ | ⚠️ 单源 | **✅ 来源可信度分级+冲突检测** |
| **卡壳自救** | ❌ 死循环 | ❌ | **✅ 6种信号自动触发重检索** |
| **假设管理** | ❌ 编造 | ❌ | **✅ 未找到的显式标注，不编造** |
| **检索职责** | 不检索 | 自己检索 | **✅ 调研委托domain-research，代码定向查** |

> **核心差异：它不是更努力地想，而是在想之前先问——"我缺什么？去哪借？借来的靠谱吗？"**

## ☸️ 三步破执

马祖道一说法，先讲"即心即佛"，再讲"非心非佛"，最后"无佛可求"。三层对应三个工程动作：

| 层次 | 禅宗 | 工程动作 | 断喝 |
|------|------|----------|------|
| **第一层** | 即心即佛——莫向外求？错，是莫只向内求 | 转向外部检索 | "你确定项目里没有？" |
| **第二层** | 非心非佛——检索到的也不能执 | 评分、校验、查版本 | "这代码什么许可证？兼容吗？" |
| **第三层** | 无佛可求——找不到就承认找不到 | 显式标注假设 | "没查到就是没查到，别编。" |

### 五个公案，五个工程映射

| 公案 | 禅宗含义 | 在 Skill 里 |
|------|----------|-------------|
| 马祖"即心即佛→非心非佛" | 三层破执 | 检索 → 校验 → 缺口标注 |
| 赵州"吃茶去" | 大道至简，不搞花活 | 找到 `pandas.describe()` 就直接用 |
| 香严击竹 | 停止刻意思考才能悟 | 卡壳时跳出推理，强制检索 |
| 风动幡动 | 一切争执源于分别心 | 方案纠结超2轮 → 评分表强制决策 |
| 云门"东山水上行" | 截断众流，打破线性思维 | 连续2轮模糊推理 → 强制切换检索模式 |

### 卡壳自动触发

执行中出现以下信号，自动中断当前操作，回到对应步骤：

| 信号 | 判定 | 回到 |
|------|------|------|
| 推理停滞 | 连续2轮"可能""大概""应该是" | Step 2 |
| 报错循环 | 同一错误修3次没解决 | Step 2 |
| 功能膨胀 | 从头实现复杂功能但没检索过 | Step 2 |
| 信息漂移 | 输出偏离用户需求 | Step 1 |
| 方案纠结 | 2个方案间反复超2轮 | Step 3 |
| 校验失败 | 同一来源验证2次不通过 | Step 3 |

## 📚 理论基础

### 心理学：苦修是自我膨胀的路径依赖

拉康精神分析发现，苦行僧守戒的痛苦作用于肉体，但潜意识在加分："我是个合格的修行人""我比那些造业的人清净"。**身体在受苦，"理想自我"却在膨胀——这不是受苦，是在投资。**

AI 智能体同理：从头推导、从头写代码，激活预训练中最频繁的模式，产生"我在认真工作"的路径依赖。即使有现成库，也视而不见。

> 伊南娜下冥府：女神每走一层脱一件华服，到最深处一丝不挂被处死。**主动剥除标签才是真修行**——对应智能体主动承认"我不知道，我需要查"。

### 工程学：环境好奇心缺失的5个根因

| 根因 | 表现 | Skill 对策 |
|------|------|-----------|
| 检索精度不足 | 关键词不匹配，好方案搜不到 | 同义词+中英文混搜，3轮关键词调整 |
| 预训练知识惯性 | 习惯心算的人计算器在手边也不用 | Step 1 强制 Gap 检测 |
| 长上下文注意力分散 | 文档太长觉得"没用" | WebFetch 精确 prompt 提取，不灌整页 |
| 规划器缺"检查现有方案" | 直接开写 | P0 优先 Glob/Grep 项目内代码 |
| 对"完成任务"的狭义理解 | 写出烂代码也算"完成" | 输出必须含"使用的资源"和"未解决的假设" |

## 🚀 快速开始

### 前置条件

- Claude Code 已安装
- Python 3.9+
- 已安装 `domain-research` Skill（调研类任务委托用）

### 使用

```powershell
# 分析任务缺口
python scripts/context_gap_analyzer.py --task "你的任务" --context "已有上下文"

# JSON 输出（便于程序化处理）
python scripts/context_gap_analyzer.py --task "你的任务" --json

# 交互模式
python scripts/context_gap_analyzer.py --interactive
```

### 8个反模式（自检清单）

- [ ] 无检索先编码
- [ ] 编造事实（"应该是""大概"）
- [ ] 封闭推理（连续2轮不引入外部信息）
- [ ] 无视文档（用户给了链接不读）
- [ ] 盲目复用（不查版本/许可证）
- [ ] **重复检索**（有domain-research却自己多平台搜）
- [ ] 海量灌入（整页网页塞进上下文）
- [ ] 隐藏假设（没查到的不标注）

## ❓ 常见问题

<details>
<summary><b>这和直接用 WebSearch 有什么区别？</b></summary>

WebSearch 是工具，破执术是**使用工具的元认知**。

它不替你搜索，而是在你即将"埋头硬推"时：
1. 先扫描你缺什么（缺口检测）
2. 判断该自己搜还是委托 domain-research（路由）
3. 搜到多个方案时帮你评分选（六维评分）
4. 查不到时逼你承认，不许编（假设显式化）

就像交通警察不替你开车，但他告诉你该走哪条路、哪条路封了、什么时候该停下来问路。

</details>

<details>
<summary><b>为什么调研类任务要委托 domain-research？</b></summary>

因为 domain-research 已经实现了多平台搜索、去重、交叉验证、评分选择。自己重新实现一遍 = 新的苦行僧模式——**重复造检索的轮子**。

破执术的定位是"交通警察"，不是"修路队"。代码类缺口（API文档、错误信息）自己定向查，调研类缺口委托专业 Skill。

</details>

<details>
<summary><b>会不会增加很多额外步骤？</b></summary>

Step 1 缺口检测是轻量的——信息充足时直接退出，不强制执行后续步骤。只有检测到高影响缺口时才触发检索。

脚本运行 <1 秒，4步工作流中 Step 2/3 只在有缺口时执行。目标是**减少返工**，不是增加流程。

</details>

<details>
<summary><b>和 RAG 有什么不同？</b></summary>

RAG 是"被动检索"——用户问了才去查。破执术是"主动断喝"——在智能体即将编造或死循环之前，强制它停下来检查。

RAG 解决"找不到信息"，破执术解决"没想到要找信息"和"找到了但不验证"。

</details>
