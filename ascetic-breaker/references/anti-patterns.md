## 1. 无检索先编码

### 识别信号
- 任务涉及代码编写，但未执行任何 `WebSearch` 或 `Glob`/`Grep` 搜索
- 直接开始写 `import` 或函数定义
- 未检查项目内是否已有类似实现

### 典型案例

**反模式**：
```
用户：帮我写一个函数，把嵌套字典展平。
助手：（直接开始写）
def flatten_dict(d, parent_key='', sep='_'):
    items = []
    for k, v in d.items():
        ...
```

**问题**：
- 项目内可能已有类似工具函数
- 可能有成熟的库（如 `flatten-dict`）更可靠
- 自写版本可能遗漏边界情况（None值、列表、特殊类型）

**正确做法**：
1. `Grep(pattern="flatten", path="src/")` 检查项目内是否已有
2. `WebSearch(query="Python flatten nested dict library")` 查找成熟方案
3. 评估是否直接用库或引用现有实现
4. 只有在确实没有现成方案时才自己写

## 2. 编造事实

### 识别信号
- 使用"应该是""大概""通常""一般来说"描述版本号、API签名、参数行为
- 给出的API参数与实际文档不符
- 引用不存在的函数、方法或配置项

### 典型案例

**反模式**：
```
用户：pandas的read_csv怎么跳过前几行？
助手：使用 skiprows 参数，应该是 skiprows=2 就可以跳过前两行。
```

**问题**：
- "应该是"表明不确定
- 没有验证 `skiprows` 的实际行为（它可以接受整数、列表或函数）
- 可能遗漏了 `header` 参数的配合使用

**正确做法**：
1. `WebSearch(query="pandas read_csv skiprows", allowed_domains=["pandas.pydata.org"])`
2. `WebFetch(url="https://pandas.pydata.org/...", prompt="提取skiprows参数的完整说明和使用示例")`
3. 基于文档给出准确答案

## 3. 封闭推理

### 识别信号
- 连续2轮以上在同一问题反复推理
- 输出中包含大量"可能是因为""也许是""让我再想想"
- 没有引入任何外部新信息

### 典型案例

**反模式**：
```
第1轮：这个错误可能是因为类型不匹配，让我检查一下...
第2轮：也可能是因为编码问题，让我再想想...
第3轮：或者是因为文件路径问题？我再分析一下...
```

**问题**：
- 三次推理都在猜，没有验证
- 应该直接搜索错误信息，找到确切原因

**正确做法**：
1. 检测到连续2轮不确定 → 停止推理
2. `WebSearch(query="完整的错误信息")` 直接搜索错误
3. 基于搜索结果定位问题

## 4. 无视文档

### 识别信号
- 用户提供了文档链接但未用 `WebFetch` 读取
- 用户提供了代码文件但未用 `Read` 读取
- 凭预训练知识回答与文档相关的问题

### 典型案例

**反模式**：
```
用户：这是我们的API文档：[链接]，帮我写个调用示例。
助手：（不读取链接，直接凭记忆写）
import requests
response = requests.post(url, json=data)
```

**问题**：
- 可能用错了认证方式（Bearer vs API Key vs OAuth）
- 可能遗漏了必需的header
- 可能请求体格式不对

**正确做法**：
1. `WebFetch(url=用户提供的链接, prompt="提取API的URL、请求方法、认证方式、请求头、请求体格式和响应格式")`
2. 基于文档内容写调用示例

## 5. 盲目复用

### 识别信号
- 搜索到代码后直接粘贴，不检查版本兼容性
- 不检查依赖是否已安装
- 不检查许可证是否允许使用
- 不检查是否与项目编码规范一致

### 典型案例

**反模式**：
```
（搜索到一段代码后直接使用）
from some_lib import some_function
result = some_function(data)
```

**问题**：
- `some_lib` 可能不在项目依赖中
- 版本可能不兼容
- 许可证可能不允许商业使用

**正确做法**：
1. 检查项目依赖文件（`Glob(pattern="**/requirements*.txt")` 或 `Glob(pattern="**/package.json")`）
2. 检查版本要求
3. 检查许可证
4. 适配项目编码规范后再使用

## 6. 重复检索

### 识别信号
- 已有专门的检索Skill（如domain-research），却自己重新实现多平台搜索逻辑
- 对调研类任务直接用WebSearch搜多个平台，而不是委托domain-research
- 重复造检索的轮子

### 典型案例

**反模式**：
```
用户：分析一下RAG架构的最新进展。
助手：（自己用WebSearch搜CSDN、掘金、知乎、B站...）
```

**问题**：
- domain-research已经实现了多平台搜索、去重、交叉验证、评分选择
- 自己重新实现质量不如专门Skill
- 本Skill的核心价值（缺口检测、方案评分、假设显式化）被稀释

**正确做法**：
1. Step 1识别出这是调研类缺口
2. 委托domain-research执行多平台检索
3. 本Skill只负责定义缺口和校验结果
4. 代码类缺口才用WebSearch/WebFetch直接检索

## 7. 海量灌入

### 识别信号
- 把整个网页内容塞进上下文
- 一次 WebFetch 后不加筛选地使用全部内容
- 上下文被大量无关信息占满

### 典型案例

**反模式**：
```
（WebFetch获取了一个100KB的页面，直接把全部内容用于回答）
```

**问题**：
- 关键信息被淹没
- 注意力分散，可能遗漏重点
- 浪费上下文窗口

**正确做法**：
1. WebFetch 的 `prompt` 参数精确指定提取目标
2. 如果页面内容很多，分多次 WebFetch，每次提取不同部分
3. 提取后做摘要，只保留与当前缺口相关的信息

## 8. 隐藏假设

### 识别信号
- 输出中没有"假设"部分
- 把未经确认的信息当作事实使用
- 未标注哪些结论基于检索、哪些基于推断

### 典型案例

**反模式**：
```
用户：帮我配置一下这个数据库连接。
助手：（假设用户用的是PostgreSQL，直接给出PostgreSQL配置）
```

**问题**：
- 用户可能用的是MySQL或SQLite
- 假设没有显式说明

**正确做法**：
1. 如果信息不足，先用 `AskUserQuestion` 确认
2. 如果无法确认，显式列出假设：
   ```
   以下配置基于以下假设：
   - 数据库类型：PostgreSQL（如果不是请告知）
   - 版本：14+
   - 认证方式：密码认证
   ```

## 自检清单

每次执行任务前，快速过一遍：

- [ ] 我是否在没有任何检索的情况下就开始写代码/方案？
- [ ] 我是否在用"应该是""大概"填充关键事实？
- [ ] 我是否连续2轮以上在同一问题上反复推理？
- [ ] 用户提供了链接/文件，我是否读取了？
- [ ] 我引用的代码是否检查了版本和许可证？
- [ ] 调研类任务是否委托了domain-research（没有自己重复多平台搜索）？
- [ ] 检索到的多个方案是否做了评分选择？
- [ ] 我是否把搜索结果不加筛选地塞进上下文？
- [ ] 我的输出中是否显式列出了未验证的假设？
- [ ] 我是否检查了项目内是否已有可复用的代码？
- [ ] 输出中是否包含"使用的现有资源"和"未解决的假设"？
