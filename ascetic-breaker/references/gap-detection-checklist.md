## 缺口分类与检查维度

### A. 版本与兼容性
| 检查项 | 影响 | 获取方式 |
|--------|------|----------|
| 依赖的库/框架版本是否明确？ | 高 | Glob搜索requirements.txt/package.json；或WebSearch+WebFetch查官方文档 |
| 编程语言版本是否明确？ | 高 | 查项目配置文件（.python-version, .nvmrc等） |
| 操作系统/运行环境是否明确？ | 中 | 问用户或查CI配置 |
| 是否存在已知的不兼容版本组合？ | 高 | WebSearch查版本兼容矩阵 |

### B. API与接口
| 检查项 | 影响 | 获取方式 |
|--------|------|----------|
| API签名是否完整（参数名、类型、返回值）？ | 高 | WebFetch官方文档 |
| API版本是否为最新？有废弃警告？ | 高 | WebFetch官方changelog |
| 认证/授权方式是否明确？ | 高 | WebFetch官方文档 |
| 速率限制或使用配额？ | 中 | WebFetch官方文档 |

### C. 数据与输入
| 检查项 | 影响 | 获取方式 |
|--------|------|----------|
| 输入数据格式、大小、编码？ | 高 | Glob搜索数据文件，Read查看样例 |
| 是否有数据样例？ | 中 | 问用户或Read样例文件 |
| 数据质量已知问题（缺失值、异常值）？ | 中 | Read数据文件分析 |
| 输出格式要求是否明确？ | 低 | 问用户，默认通用格式 |

### D. 领域知识
| 检查项 | 影响 | 获取方式 |
|--------|------|----------|
| 是否涉及专业领域（医疗/金融/法律）？ | 高 | 委托domain-research |
| 是否需要最新政策法规？ | 高 | 委托domain-research |
| 行业术语或标准需要确认？ | 中 | 委托domain-research或WebSearch |
| 数据时效性要求？ | 高 | 委托domain-research |

### E. 现有资产（P0优先级，不联网）
| 检查项 | 影响 | 获取方式 |
|--------|------|----------|
| 项目内是否已有类似功能代码？ | 高 | Grep搜索关键词 |
| 是否有项目工具函数库？ | 中 | Glob搜索utils/helpers目录 |
| 编码规范（linting配置）？ | 中 | Glob搜索.eslintrc/.pylintrc等 |
| 测试框架和现有测试模式？ | 中 | Glob搜索test目录，Grep测试代码 |
| 统一错误处理/日志方案？ | 中 | Grep搜索错误处理和日志代码 |

## 缺口评分标准

### 影响程度评分

| 等级 | 判定标准 | 必须解决？ | 未解决时处理 |
|------|----------|-----------|-------------|
| **高** | 直接影响结果正确性：版本不兼容、API签名错误、数据格式错误、关键事实编造 | 是 | 必须检索或向用户确认，不能跳过 |
| **中** | 影响质量但不影响基本功能：编码规范、最佳实践、性能优化 | 尽量 | 无法解决时标注假设，使用默认方案 |
| **低** | 锦上添花：输出格式、命名风格、注释风格 | 否 | 使用通用默认值，不标注 |

### 评分决策流程

```
缺口是否影响代码能否运行/结果是否正确？
├── 是 → 高影响
│   └── 是否有现成来源可以查？
│       ├── 是 → 必须检索
│       └── 否 → 必须向用户确认（AskUserQuestion）
└── 否 → 缺口是否影响代码质量/可维护性？
    ├── 是 → 中影响 → 尽量检索，否则标注
    └── 否 → 低影响 → 使用默认值
```

## 复查流程

初次缺口识别后，执行以下复查（最多2轮）：

### 第一轮复查：遗漏检查
- [ ] 是否检查了所有5个缺口类别（A-E）？
- [ ] 任务描述中的每个关键名词是否都已确认其版本/格式/来源？
- [ ] 用户提供的链接/文件是否都已读取？（容易遗漏）
- [ ] 是否有隐含的依赖关系未考虑？（如用了A库但B库是A的依赖）

### 第二轮复查：误报检查
- [ ] 已标记的缺口是否在用户提供的上下文中实际已有答案？
- [ ] 是否有缺口其实不影响当前任务？（如任务不涉及该功能）
- [ ] 获取方式是否合理？（能用Glob解决的不要WebSearch）

### 复查结果处理
- 发现遗漏 → 补充缺口清单，重新复查
- 发现误报 → 从清单中移除
- 复查通过 → 进入Step 2

## 按任务类型的专项检查

### 代码开发任务
额外检查：
- [ ] 依赖清单文件是否存在？（Glob搜索requirements.txt/package.json/go.mod等）
- [ ] 项目目录结构是否了解？（Glob搜索）
- [ ] 是否有README/CONTRIBUTING说明编码规范？
- [ ] 错误处理模式是否统一？（Grep搜索现有错误处理）
- [ ] 是否有CI配置暗示测试/构建要求？

### 调研分析任务
额外检查：
- [ ] 时间范围是否明确？（默认近12个月）
- [ ] 数据来源是否有权威性要求？
- [ ] 目标读者是谁？（技术/管理层/通用）
- [ ] 是否需要对比维度？
- **此类缺口统一委托domain-research获取**

### 方案设计任务
额外检查：
- [ ] 技术栈是否有限制？
- [ ] 规模要求（用户量/数据量/并发）？
- [ ] 预算/时间约束？
- [ ] 是否有现有架构需要兼容？
- **选型对比类缺口委托domain-research，技术可行性类缺口WebSearch**

## 检测输出模板

```markdown
## 上下文边界检测报告

### 任务目标
[一句话描述]

### 任务类型
[ ] 代码开发  [ ] 调研分析  [ ] 方案设计  [ ] 通用

### 已有信息
- [信息1]
- [信息2]

### 缺口清单
| # | 缺口 | 类别 | 影响 | 获取方式 | 委托对象 |
|---|------|------|------|----------|----------|
| 1 | [描述] | A/B/C/D/E | 高/中/低 | [具体方式] | 本Skill/domain-research/用户 |

### 复查记录
- 第一轮复查：发现[N]个遗漏，已补充
- 第二轮复查：发现[N]个误报，已移除
- 复查结果：通过/未通过（原因）

### 判定
- [ ] 无高影响缺口 → 退出Skill，直接执行
- [x] 有高影响缺口 → 进入Step 2
```
